REGRA OBRIGATÓRIA DO PROJETO WMCPLAYER

NUNCA criar consultas automáticas repetidas, polling, setInterval de rede ou loops para consultar Cloudflare, Supabase ou Efí.

ARQUITETURA REALTIME OBRIGATÓRIA:
1. CLIENTE:
   - somente 1 canal Realtime aberto por cliente autenticado
   - nome: wmcplayer-client-<ID_DO_CLIENTE>
   - todos os eventos do cliente passam por esse mesmo canal
2. ADMIN:
   - somente 1 canal Realtime administrativo compartilhado
   - nome: wmcplayer-admin
   - todas as telas administrativas recebem ordens por esse mesmo canal
3. LIMPEZA:
   - remover o canal ao sair da tela autenticada, trocar de página ou deslogar
   - remover canais antigos antes de abrir o canal único
   - nunca recriar canal porque o perfil, saldo ou status mudou
4. EDGE FUNCTIONS:
   - não abrir WebSocket para enviar ordens
   - enviar Broadcast pela API REST do Supabase Realtime
   - PIX, ativação, confiança e movimentações devem mandar payload/ordem
5. CONSULTAS:
   - somente uma vez ao entrar, abrir, recarregar ou clicar manualmente em atualizar/verificar
   - uma ordem recebida pode atualizar a tela pelo payload
   - se uma tela precisar de dados adicionais, pode fazer uma única consulta causada pela ordem
   - nunca usar timer para consultar status
6. PIX:
   - cliente gera a cobrança uma única vez
   - Efí confirma pelo webhook
   - Edge Function altera banco e envia ordem no canal único do cliente e do admin
   - tela aplica o payload recebido sem consultar status em loop
7. ATIVAÇÃO PELO SUPORTE:
   - admin confirma
   - Edge Function envia notificação e ordem Realtime
   - tela atualiza automaticamente pelo payload recebido

INTERVALOS LOCAIS PERMITIDOS:
- cronômetro visual do PIX
- relógio da programação
- jogos e animações
- verificação local da permissão de notificação

Esses intervalos locais nunca podem executar fetch, RPC, consulta Supabase ou chamada Cloudflare.
