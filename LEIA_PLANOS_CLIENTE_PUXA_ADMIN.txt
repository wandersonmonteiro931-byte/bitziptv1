CORREÇÃO: CLIENTE NÃO PUXAVA PLANOS DO ADMIN

BASE USADA:
bitziptv1-planos-id-null-corrigido.zip

PROBLEMA:
Admin mostrava planos com 15%, 20%, 30%, mas o cliente continuava vendo fallback 5% e 10%.

O QUE FOI CORRIGIDO:
1. Cliente agora busca os planos pelo RPC get_active_renewal_plans.
2. Se o RPC falhar, ainda tenta buscar direto na tabela iptv_renewal_plans.
3. SQL cria a função get_active_renewal_plans.
4. SQL mantém política de leitura para usuário logado.
5. Continua sem realtime, sem polling e sem consultas automáticas.
6. Cliente consulta apenas ao carregar/logar/recarregar/verificar app.

COMO APLICAR:
1. Extraia o ZIP.
2. Abra bitziptv1-main.
3. Clique em ATUALIZAR_GITHUB_AGORA.bat.
4. Aguarde o Cloudflare publicar.
5. No Supabase, rode novamente SQL_CRIAR_PLANOS_RENOVACAO.sql.
   Pode rodar por cima. Não apaga seus planos.
6. No cliente, faça novo login ou recarregue a página/atualize o app.

IMPORTANTE:
Não foi ativado realtime nem polling para economizar o plano gratuito.
